# 运行与故障处理

## 日常操作

1. 在“Campaign”页创建区域策略，只选地区/国家、一个或多个产品赛道、客户类型和优先级。将需要开发的 Campaign 设为“运行中”；暂停只停止该策略参与新发现，不删除已有客户或历史归属。
2. 打开“自动发现”页确认运行中 Campaign、时区和已启用来源，然后点击“开始引擎”。开始操作会同步来源并持久化运行状态；独立 Cron 在下一个 15 分钟触发点运行批次，关闭浏览器不会改变状态。
3. 使用“暂停”临时停止调度，使用“恢复”继续，使用“停止”结束当前运行。已写入的运行、候选和证据不会被删除。
4. 主界面只显示“今日已完成”，即当天通过筛选、去重并保存的合格客户数；原始发现、解析、官网核验、有效联系、重复、强制门槛失败和失败只在批次与审计明细中显示，不构成配额或停止条件。
5. “统一客户库”每家公司只显示一次；顶部客户范围使用地区、国家、客户类型和产品分类筛选，联系状态、来源、重复/拒联状态和评分位于更多筛选。公司可同时命中多个客户类型、产品方向和 Campaign；详情会显示主 Campaign、其他当前匹配和历史归属。列表按页读取，证据只在打开客户详情时加载。
6. 只有人工批准的合格线索可以导出 CSV；导出不会写生产 CRM，也不会发送消息。
7. 新来源、手工补采、重新核验、研究任务书和数据导入都位于“高级工具”；它们用于维护和故障处理，不是每日主流程。

## 后台 Cron

后台每次只运行一个来源批次，计划频率仍为每 15 分钟。Sites 应用部署和 Cron 启用是两件事。当前唯一正式调度为 `worker/cron-proxy.ts` 与 `wrangler.cron.jsonc`：独立 Worker经 Sites 的受保护 API 触发批次，继续由 Sites 应用读写原有私有 D1；`SITES_BYPASS_TOKEN` 只作为 Cloudflare Worker secret 保存，不写入源码。Sites 应用不再保留直接绑定 D1 的第二套 Cron 备选入口。

每批最多领取 20 个候选，初始公司级并发为 3。连续 4 个健康结果且滚动错误率低于 25% 时逐级升并发，最高为 5；403/429 立即降为 1，超时降为 2，最近 6 个结果的错误率达到 25% 时降为 2、达到 50% 时降为 1。逐域名请求仍按来源的 `rate_limit_ms` 串行限速，同公司名或同注册域名不会重复并发。

当前上线核验：

- Cron 目标 URL 是当前 owner-only Lead Engine Sites 项目；机器令牌以 `secret_text` 保存，没有出现在源码或日志中。
- Sites slug 或生产 URL 变化后，必须同步更新 `wrangler.cron.jsonc` 的 `LEAD_ENGINE_URL`、重新部署 Cron Worker，并在下一个 15 分钟触发点核对 Sites 控制请求和 D1 心跳。旧 URL 返回 404 时，界面即使显示 running 也不会继续产生批次。
- 正式 Trigger 为 `*/15 * * * *`；Worker 的 `workers.dev` 和 Preview URL 均关闭。
- `ENABLE_PAID_PROVIDERS=false`，没有生产 CRM、官网 D1/R2 或发信凭据。
- 2026-08-15 首个真实 Cron 获得 HTTP 200；停止态下 `last_run_at` 不推进。负责人启动引擎后，应继续核验 `last_heartbeat_at` 推进和完整运行日漏斗。

## 来源与解析器

- `vision_council_members`：协会会员表。
- `mido_exhibitor_map`：MIDO 服务端展商地图；读取企业官网、国家、类别和公开通用商务邮箱，排除中国大陆展商。
- `exhibitor_cards`：直接官网链接或同域展商详情页，再从详情页解析企业官网。
- `exhibitor_text`：纯文本名称。没有官网时只能交给明确批准并配置的 provider；默认不会合格。
- `dynamic_directory`：仅用于已确认的公开 JSON endpoint；配置 `itemsPath`、`nameField`、`websiteField`、`detailField`。
- `pdf_directory`：公开官方 PDF；最大 6 MB、100 页，抽取结果仍只是名称线索。
- `generic_links`：公开页面上的直接外部企业链接。

所有解析器都有持久化 `offset` 游标。大型且已确认的公开目录可在同一运行日每 15 分钟继续下一批，每批最多 20 家；普通来源每天最多运行一次。候选完成并写入批次明细后才按连续序号提交游标，因此中断只会从最后安全断点继续；已保存的后续候选即使重读也会由公司级去重拦截。到达末尾后游标归零，记录完整扫描时间，并把该来源延后 7 天。

## 告警与恢复

- 来源超时、非 HTML/JSON/PDF、robots 禁止、登录/付费要求或解析失败：记录 attempt、来源健康和错误摘要，然后切换其他到期来源。
- 12 分钟以上仍为 `running` 的运行会在下一次调度前恢复为失败，避免请求中断后阻塞后续批次；候选游标只推进到最后连续完成的安全断点。
- 所有到期来源暂时耗尽：记录来源健康提醒并延后重试；引擎保持 running，不生成每日目标缺口。
- 动态来源没有公开 endpoint：保持禁用；确认 endpoint 后通过来源 API 写入配置并启用。
- 联系方式失效或官网变化：执行手工重新核验；旧证据不删除，新证据和新评分追加留痕。

## 安全限制

请求只允许公共 HTTP/HTTPS、标准端口，限制重定向、超时、内容大小和速率，并阻止本地、内网、保留地址与常见社交/电商聚合域名。系统尊重明确的 robots `Disallow`，不绕登录、验证码或付费墙。

当前没有自动发信能力和凭据。Campaign 中保存的外联配置固定为关闭，并预留“回信即停、退信即停、退订即停、人工接管回复”等边界；在负责人另行确认发件身份、每日/域名限额、退订文案和合规范围前，不得启用。

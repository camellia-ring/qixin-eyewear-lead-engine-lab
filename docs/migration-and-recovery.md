# Lead Engine迁移与恢复

仅在任务涉及数据库变更或已确认运行事故时使用。无schema/data影响的文档或界面修改不触发全库备份、停引擎或迁移。

## 数据变更

- 检查目标实例与实际迁移账本，只应用尚未应用且属于本次范围的迁移；不按旧手册重复执行0003/0004等历史步骤。
- 影响schema/data前导出对应目标的备份并记录来源、时间与哈希，核对恢复方式。知识库只保存路径与摘要，不复制客户行。
- 当前采取兼容的前向变更，保留旧记录；对新旧库场景验证约束与数据保留。破坏性清理、重建或恢复唯一数据库不属于普通发布授权。
- 发布后核对本次涉及的schema与业务行为；并发业务活动导致的行数变化要区分，不能把总行数固定等于备份当成所有发布的要求。

## 运行事故

先只读取证，判断故障影响。只有风险和已有事故处置授权支持时才暂停引擎/Cron；普通局部失败不自动停整个系统。隔离复现和恢复准备可先完成。

回退应用代码不恢复D1。数据恢复先在独立目标验证内容和兼容性，重绑定/覆盖生产需要对应授权。保存故障证据与恢复结果，不能为“恢复干净”删除历史。

具体发布授权见 [AGENTS](../AGENTS.md)，常规操作见 [operations](operations.md)。[旧迁移与恢复原文](history/2026-09-12/migration-and-recovery.md)仅作历史，不重放其固定顺序。
